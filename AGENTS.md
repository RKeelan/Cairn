# AGENTS.md

Cairn is a shopping list for Android phones and Wear OS watches. `README.md` describes the modules and lists the commands.

## Commands

Run `./gradlew check` before handing work off. It runs ktlint, the unit tests, the coverage check and Android Lint, as CI does. `./gradlew ktlintFormat` fixes formatting.

CI also runs `./gradlew :core:integrationTest` against a local Supabase stack. Run it after changing anything in `supabase/` or in `SupabaseServer`.

Unit tests must cover at least 75% of the code Kover measures. Composables and activities are left out of the measurement, and so is the Supabase client, which the integration tests cover. Keep logic in `:core`, where tests reach it.

## Supabase

`supabase/migrations` defines the tables and the functions the apps call, and `docs/data-model.md` describes them. Change the description with the tables. A change to a function's arguments or to what it returns changes `SupabaseServer` with it, and the fake server in `core/src/testFixtures`, which follows the same rules.

Run the CLI as `bunx supabase`, which uses the version `package.json` pins. `bunx supabase db reset` loses what the local stack holds, the accounts included. CI starts a local stack from the migrations and the seed data, and lints the database with `bunx supabase db lint`.

Never link to, push to, or otherwise change a hosted Supabase project without the maintainer's agreement.

## Emulators and devices

Always start an emulator with `-no-audio`, headless or not: without it the emulator opens an audio stream to the host, which makes the PC's speakers pop. Set `ANDROID_SERIAL` before any adb command, and never install on a physical device without the maintainer's agreement. Never publish to Google Play, or run anything else that talks to it, without the maintainer's agreement.

## Public repository

Treat everything in this repository as public: files, commit messages, branch and tag names, and the text of issues, pull requests, reviews and releases. Write all of it for any developer, never to or about a particular person, and keep the developer's private information out of it:

- No paths from the developer's PCs. Write paths relative to the repository, or with placeholders such as `<root>`, `~` and `%LOCALAPPDATA%`.
- No machine names, tailnet names, or addresses on the developer's network.
- No email addresses.
- No names of the developer's family, friends or colleagues, and nothing about where the developer lives or works.
- No personal files, images or screenshots. Test data is made up or generated by the tests.
- No keys, tokens, passwords or signing material.
- No working material: no inline review notes, agent plans, state files or handoffs. Open questions and planned work go in issues.

## Dependency Policy

All dependencies and Gradle plugins are pinned to exact versions in `gradle/libs.versions.toml`, and the build fails on a dynamic or changing version. The Supabase CLI is pinned in `package.json`, and GitHub Actions are pinned to commit SHAs. Do not use version ranges. Dependabot handles upgrades.
